# Task 2：GPU 数据存在哪里

[English](note.en.md) | 简体中文

在向量加法中，输入数组 `A`、`B` 和输出数组 `C` 都位于**全局内存（Global Memory）**。在独立显卡上，全局内存由显存承载。"全局内存"描述程序访问的空间，"显存"描述保存数据的硬件。

每个线程负责自己的元素 `i`，流程分为三步：

1. **读取：** 线程把 `A[i]` 和 `B[i]` 从全局内存读入自己的**寄存器（Register）**。读取是复制值，`A[i]` 和 `B[i]` 中的原值仍然保留。读取需要时间：先发出请求，数据稍后才到达。
2. **相加：** **执行单元**使用寄存器中的值计算和，结果先保存在寄存器中。寄存器负责保存，执行单元负责计算。
3. **写回：** 线程把结果写入全局内存中的 `C[i]`。完成这一步之后，`C[i]` 才会更新。

例如计算 `C[2] = A[2] + B[2]` 时，线程读取 3 和 30，相加得到 33，再把 33 写入 `C[2]`。

同一 Wavefront 的各个 Lane 一起发出读取请求，每个 Lane 提供自己的地址。相邻 Lane 读取相邻元素时，硬件可以把这些请求合并处理，这称为**合并访存（Memory Coalescing）**。**缓存**（Cache）中可能已经有所需数据的副本。合并访存取决于地址怎样排列，缓存命中取决于是否已有副本。

**LDS**（Local Data Share，HIP 中写作 `__shared__`）是同一个 Block 内线程交换结果的空间。例如求和时，线程需要合并各自的部分结果：先写入 LDS，在 `__syncthreads()` 处等待，然后再读取。向量加法不需要 LDS，因为每个线程处理的元素互不依赖。

**对最初理解的修正：** 我最初以为数据会放进寄存器，Wavefront 中的每个 Lane 都能访问这些数据，并且结果会写入 LDS。实际上，数组一直位于全局内存。每个线程只把自己的输入读入自己的寄存器，Lane 之间不会读取彼此的寄存器。结果写回全局内存中的 `C[i]`，而不是写入 LDS。
