# Task 5：使用 Agent 辅助优化向量加法

[English](note.en.md) | 简体中文

实验环境：AMD Radeon Cloud（One-click 资源组），AMD Radeon Pro W7900D（gfx1100，48 个 CU，wave32），HIP 7.15。运行时间为 2026-11-02（UTC）。Agent：Claude Code（Claude Opus 5.5）。

## 提供给 Agent 的信息

- **显卡：** AMD Radeon Pro W7900D，gfx1100。
- **代码：** 第 8 章 HIP 向量加法 `vector_add_v0`（一个线程处理一个元素，默认 block 256）。
- **正确性检查：** 程序在计时前后都与 CPU 参考结果对比，`correct`、`precheck`、`postcheck` 都必须是 `OK`。
- **计时方式：** GPU event，warmup 10，repeat 50，N = 16,777,216 个 `float32`，每个进程取中位数。

关键提示词：“解释这个向量加法 kernel，提出一个简单的优化建议，例如调整线程块大小。保留原始版本，只做一次修改，先检查正确性，再用相同的输入规模和计时方式对比两个版本。”

## Agent 的解释与建议

向量加法每搬运 12 字节只做一次加法，速度受显存带宽限制（memory-bound），而不是受计算限制。Agent 建议尝试不同的线程块大小（block size），然后在文件副本中把程序的默认 block 从 256 改为 512（只改一行：`int block = 512;`），原始文件保持不变。

## Block 大小扫描

确定 512 之前，Agent 测量了五种 block 大小。各 block 大小在 3 轮中交替运行，以减少运行顺序的影响。所有运行都通过了正确性检查。

| Block | Grid | 多次运行的中位数 |
|---:|---:|---:|
| 64 | 262,144 | 0.2952 ms |
| 128 | 131,072 | 0.2816 ms |
| 256（原始） | 65,536 | 0.2808 ms |
| 512 | 32,768 | 0.2794 ms |
| 1024 | 16,384 | 0.2951 ms |

第一次不交替的扫描结果有误导性：每种 block 大小的第一个进程约 0.295 ms，之后的进程约 0.280 ms。调换运行顺序后才发现了这个问题。

## 修改前后对比

两个版本交替运行，各 5 个独立进程，输入和计时方式完全相同。

| 版本 | 正确性 | 5 个进程的中位数 | 范围 |
|---|---|---:|---:|
| 原始（block 256） | OK ×5 | 0.2810 ms | 0.2802–0.2958 ms |
| 修改后（block 512） | OK ×5 | 0.2802 ms | 0.2791–0.2956 ms |

在不能整除的长度 1,000,003 下，两个版本也都通过了检查（0.0208 ms 对比 0.0213 ms）。

## 总结

- **Agent 改了什么：** 默认线程块大小，从 256 改为 512。
- **结果是否正确：** 正确，所有运行都通过了检查。
- **是否变快：** 没有明显加速。两者只差约 0.3%，而两个版本的单个进程时间都在约 0.280 ms 和 0.295 ms 之间跳动，噪声比改动带来的差异还大。
- **学到的东西：** 对向量加法这种受带宽限制的 kernel，block 大小在 128 到 512 之间几乎没有影响；在这次扫描中，太小（64）或太大（1024）的 block 慢了约 5%。公平对比需要相同的输入、相同的计时方式、多次独立运行，并交替运行顺序。
